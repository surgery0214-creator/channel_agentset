# BBchannel 对话配队助手 v0.5

在 Windows 上双击项目根目录的 **启动配队助手.cmd**。精确编辑和换人编排需要 Python 3.10+、Tkinter 和 LangGraph。在项目根目录用启动脚本所用的 Python 安装依赖。

~~~powershell
python -m pip install -r team_agent/requirements.txt
~~~

基础配队、预设匹配和导出仍支持 Python 3.9+ 的标准库环境。智谱、本地 Ollama 和离线句式共用同一套本地校验与导出逻辑。

## 精确修改已有回合（v0.4）

加载「摩根_光狐_光狐」后输入「第二面把二号位光狐一技能移到最前」。助手会把原来的第 8 项移到第 1 项。第一面有三个回合，可用「查看第一面第二回合」列出每项的编号，包括条件开始和条件结束的位置。

~~~text
第一面第二回合把二号位光狐二技能改给三号位
第一面第二回合在第2项前插入摩根三技能
第一面第二回合删除第2项
第二面把第3项移到第2项
~~~

「最前」「最后」指当前连续动作段的两端。条件标记、换人和特殊动作都是段的边界。「改给」「删除」只编辑选中的一项。角色重名或技能出现多次时，助手会列出候选，可回复「好友那只」「第二次」或完整选项。「取消」丢弃待处理的整条指令，「撤销」恢复上一次修改前的草案。

## 御主礼装与换人（v0.5）

下面用一支新队演示完整流程。新建时按站位依次填写三至六位从者。也可以直接载入带后排的预设，或对已有队伍说「四号位放奥伯龙」填入空后排。

~~~text
新建队伍：公主、光狐、光狐、奥伯龙，助战三号位
御主礼装换成迦勒底战斗服
第二面让三号位光狐先给一号位公主充能，再用换人服把三号位光狐换成四号位奥伯龙，然后奥伯龙开一技能
第二面公主放宝具
第三面追加：奥伯龙二技能给公主
第三面公主放宝具
查看第二面第一回合
~~~

这段指令会将第二面的技能编码成 [[7,1],[12,4,3],7]。换人后奥伯龙位于三号位，下一面的二技能给公主编码成 [8,1]。助手把原始队伍和助战信息写入预设，并按技能执行顺序推演礼装换人。打开预览可核对技能和宝具实际对应的站位。可以用「第一面插入御主一技能」编排御主动作，有目标的技能可写作「第一面插入御主二技能给公主」。

推演依据预设记录的动作。遇到条件换人、可能换人的额外回合或退场补位记录，后续依赖站位的编辑会提示在原程序核对。实战中的阵亡、技能冷却与宝具能量请在游戏中验证。

## 按自己的从者找队伍

可以直接问「我有公主和一只光狐，能用哪套？」。助手用这份临时名单检查本地预设，列出需要借的从者和站位。回复「用第一套」载入选中的队伍，原预设的技能、宝具、换人和出卡顺序会一起带入。载入后仍可预览、编辑支持的回合、撤销或另存。

要跨会话复用名单，可逐句输入：

~~~text
登记从者：公主、光狐
可借助战：光狐
匹配预设
用第一套
~~~

窗口顶部的「我的从者」可以查看名单。「登记从者：光狐×2」把光狐的数量设为 2，其余从者继续保留。「移除从者：光狐」移除这项登记。「可借助战」设置的是完整可借名单，可以用「可借助战不限」恢复默认。个人名单保存在这份 BBchannel 安装目录的 team_agent_collection.sqlite3 中。临时试配、查看名单和取消角色重名追问都不会登记角色。

匹配时，助手检查六个位置中的每个已配置角色，只扣除原预设明确指定的那一位助战。遇到不匹配会列出最接近的预设及缺口。名单只记录角色与数量，技能等级、伤害、关卡适配和好友实际穿戴的礼装仍需按自己的账号核对。

## 第一次配队

1. 输入「用公主双光狐队。第二面只让三号位光狐开一技能给公主，然后公主开宝具。其他照旧。」
2. 在右侧核对队伍和三面的行动顺序。第二面应显示「3号位1技能给1号位 → 1号位宝具」。也可以继续说「第二面追加二号位光狐三技能给公主」。
3. 点击「导出新预设」，输入一个新名字。助手会在 BBchannel 的 settings 文件夹中另存 JSON。同名文件会提示换名。
4. 在 BBchannel 的文件菜单选「打开队伍配置」，选择新文件。核对原程序显示的前排、助战、技能和宝具后，即可按原来的方式使用脚本。

也可以从空队开始。依次输入下面几句话，每句发送一次。

~~~text
新建队伍：摩根、光狐、光狐，助战三号位
第一面：摩根一技能，二号位光狐一技能给摩根，摩根开宝具
第二面：三号位光狐一技能给摩根，摩根开宝具
第三面：摩根开宝具
导出 我的摩根队
~~~

这个例子演示动作编排。能否在每面开出宝具取决于实际礼装、练度和敌方配置。

## 对话行为

加载「爱尔奎特_光狐_光狐」后，可以连续发送三句话：

1. 「第二面让光狐给公主充能。」助手列出两只光狐的站位。
2. 「好友那只。」助手按当前队伍的助战位确认施法者。
3. 「把刚才的充能挪到第三面。」助手把该次充能从第二面移到第三面技能列表末尾，保留施法目标和两面的宝具。预览中，两面都标有「本次修改」。

如果上一条指令同时指定了多个充能，助手会列出候选动作。也可回复「自家那只」「好友那只」或候选动作的完整名称。明确的「把刚才的充能挪到第三面」可以直接在本机执行；其他自由表述由所选模型解析。重新加载队伍会清除上支队伍的技能引用。输入「撤销」能恢复移动前的技能顺序。

- 首版可以编排国服、三位固定前排、每面一个回合的配置。技能在宝具之前执行，可按序指定不同站位的宝具。预览会显示站位，方便区分两只同名从者。
- 写「第二面三号位光狐一技能给公主」会替换第二面的技能列表，沿用该面的宝具。写「追加」会保留已有技能。写「第二面不开宝具」可以清空该面的宝具。
- 助手遇到重名或缺少技能目标会追问。直接回复「二号位」即可。「取消」结束追问，「撤销」回退上一次草案修改。一次消息中的动作全部通过校验后才生效。
- 带后排的模板可载入、预览和另存。多回合、条件或已有出卡策略的面可通过精确编辑指令修改普通动作。会话草案和等待回答的追问保存在内存，导出后可再次加载队伍。
- 从模板开始会沿用模板里的助战和战斗参数，设备、补充 AP 和停止条件等运行设置取自当前安装的 page0。从空队开始默认仅按从者选助战，御主礼装和助战筛选数值沿用 page0。

## 自由表达与终端入口

窗口顶部可随时选择模型来源，下一条配队指令使用选中的服务，当前队伍和对话进度会保留。

- **智谱 API** 默认使用 glm-4.6v。可在密码框中输入密钥，或者设置环境变量 ZHIPUAI_API_KEY。安装了 pywin32 的 Windows 也可读取当前用户的「BBchannel.TeamAgent/BigModel」凭据。密码框里的编辑仅在本次运行有效。智谱收到配队指令、近期对话和相关队伍资料。[智谱 GLM-4.6V](https://docs.bigmodel.cn/cn/guide/models/vlm/glm-4.6v)
- **本地 Ollama** 填写已安装的模型名称，使用本机 11434 端口。API Key 仅用于智谱。
- **离线句式** 可直接使用上面的示例，全部在本机执行。预设加载按钮、预览、撤销和导出在三种模式下均由本机处理。

在项目根目录也可通过 PowerShell 使用终端对话，输入「退出」结束。通过 --provider 选择 bigmodel、ollama 或 offline。为兼容旧版，单独传入 --model 或在终端模式设置 BB_AGENT_MODEL 时，默认选择 Ollama。直接双击启动脚本会选中智谱 API。

~~~powershell
python -B -m team_agent --cli
python -B -m team_agent --cli --provider bigmodel
python -B -m team_agent --cli --provider offline
python -B -m unittest -v team_agent.test_agent
python -B -m unittest -v team_agent.test_battle_edit
~~~

项目入口是 __main__.py。dialogue.py 管理会话与草案，core.py 处理角色库和 BBchannel 配置。edit_language.py 解析离线编辑句式，battle_edit.py 处理站位、技能与礼装。edit_graph.py 使用 LangGraph 的 StateGraph、内存检查点、interrupt 和 Command 恢复追问。图在临时副本上校验整条指令，成功后一次性提交到会话。model.py 对接智谱和 Ollama。[LangGraph 追问与恢复](https://docs.langchain.com/oss/python/langgraph/interrupts) · [Ollama 聊天接口](https://docs.ollama.com/api/chat)

单元测试在临时目录生成虚构的角色表、单回合预设和多回合预设。仅复制 team_agent 下的 Python 文件，也能运行上面的 unittest 命令。实际配队使用 BBchannel 安装目录中的角色资料和玩家预设。
